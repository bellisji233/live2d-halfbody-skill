# 出图：从一张立绘到分好的图层

有画师按 [图层清单](图层清单.md) 交分层文件时，跳过这一页。只有一张立绘时，全程由图像模型和代码完成：

1. 按绑定要求生成立绘（`提示词/标准/A0-base.txt`），给用户确认。
2. 生成 13～17 张“整张图改一处”的变体，每张自动检查对位。
3. 代码把立绘和变体拆成图层（自拆），作为合成的底。
4. See-through 把立绘拆成看得见的图层，和自拆合成最终图层。
5. 以最终图层的静止合成为底，再出 4 张变体：脸红、招手、摊手、指向，拆成手势层和脸红层。

分工：切图靠 See-through，图像模型只补它给不了的细节。用户在这一段看一次：立绘定稿；另外答应一次：立绘传到 See-through（Hugging Face，备用魔搭；本机跑时不用传）。

## 先把立绘设计成好拆的样子

A0 的提示词把这些要求直接写进去，换角色时只改外貌和服装：

- 脖子清楚可见，约头宽的三分之一，两侧有轮廓线；下巴和领口之间露出一段脖子。
- 刘海可有可无。有刘海时刘海短，两条眉毛完整露出，不在额头上投影；没有刘海时露出整个额头和发际线。
- 两侧头发二选一：整片挡在耳朵前面，到下巴为止，末端有清楚的轮廓；或者全部别在耳后，两只耳朵完整露出。都不要零碎发丝横过脸。
- 头发和皮肤不同色：头发有细轮廓线、冷色阴影；皮肤暖色阴影。
- 短发：末端停在下巴高度，不压到肩膀。长发：垂在脖子、肩膀和背后，只从脖子两侧和手臂外侧露出来，手臂和身体之间的缝里不露，不搭在肩膀、胸前或手臂上。双马尾：在耳朵后上方扎起，垂在肩膀后面。
- 帽子类饰物戴在头顶，不遮额头和眉毛。
- 腮红在脸颊里，不碰脸的轮廓。
- 眼镜可有：细框、镜片透明、没有反光，镜框和睫毛、眉毛之间留缝。
- 耳坠可有，要头发别在耳后：从耳垂垂下的小坠子，不碰头发、下巴、脖子和肩膀。
- 平光，不要投影；纯白底；没有垂下的飘带、横过脖子或脸的饰物（眼镜除外）。项链只能是贴在衣服上的细链，最多一个吊坠，不碰头发、脖子和手臂。
- 发夹之类的小配饰放在头发上，不碰脸。
- 正面半身，从帽顶到腰；左右留出空白。头顶空白不够时，拆层时用 `--pad-top` 在上方补白边。

## 变体

`提示词/标准/` 是一套完整的提示词，文件名就是变体名。每张以表中的“底图”为底，只改一件事：

| 变体 | 底图 | 改什么 | 用来 |
|---|---|---|---|
| S1-segment | 立绘 | 各部位涂成纯色（见下） | 每个图层在立绘上看得见的范围 |
| V1-hat-off | 立绘 | 拿掉帽子，补出头顶 | 刘海、侧发在帽子下面的范围 |
| V2-side-off | V1 | 拿掉两侧头发（连同上面的发夹），补出耳朵、脸边、后发 | 侧发的范围（头发别在耳后时不出） |
| V3-bangs-off | V2 | 拿掉刘海（连同上面的发夹），补出额头和发际线 | 刘海的范围；刘海下面 See-through 没画的后发（没有刘海时不出） |

| V9-dangles-off | 立绘 | 拿掉吊坠，补出后面的衣服 | `Dangle_*` 和吊坠下面的衣服 |

| P1～P3 | R0-rest | 招手、摊手、指向 | `Pose_Wave`、`Pose_Explain`、`Pose_Point` |

S1 的颜色：帽子 `#FF0000`，刘海 `#0000FF`，侧发 `#00FF00`，其余头发（含长发）`#FFFF00`，双马尾（从发绳往下）`#8000FF`，脸（含耳朵、五官、眼镜、耳坠）`#FF00FF`，脖子 `#00FFFF`，身体（含项链、吊坠、包带）`#FF8000`。没有帽子的角色不出 V1，S1 里也没有红色；头发别在耳后的角色不出 V2，S1 里也没有绿色；没有刘海的角色不出 V3，S1 里也没有蓝色。

`素材/角色名/` 里放定稿立绘 `A0-base.png` 和 `prompts/`：从 `提示词/标准/` 整个复制过来，把 `[[…]]` 换成这个角色的描述（A0、V1、V2、V8、V9 里有）。A0 里选好头发长短（短发、长发、双马尾）、有没有刘海、侧发在耳前还是耳后，没有眼镜、耳坠的删掉那一行。没有帽子的角色删掉 V1 和 S1 里帽子那一行；头发别在耳后删掉 V2 和 S1 里侧发那一行；没有刘海删掉 V3 和 S1 里刘海那一行；没有挂件删掉 V9。删掉的那一步，`variants` 自动改用前一步作底（没有刘海时 V4 以 V2 为底）。还留着 `[[` 的提示词 `variants` 不会生成；`prompts/` 里没有的变体跳过。

```
python -m rigkit.variants 素材/角色名                 # 依次生成缺的变体，每张出检查图
python -m rigkit.split 素材/角色名 素材/角色名/layers --pad-top 90
```

用其他图像工具出图时，`variants 素材/角色名 --list` 列出每张要附的图和提示词；出好存进 `素材/角色名/` 后再跑 `variants`，已有的图只做检查。要求见 SKILL.md 第 2 步。

`variants` 在 `素材/角色名/check/` 里给每张变体出一张“底图 | 变体 | 差异”检查图，`report.json` 记下偏移和变化面积。偏移 4 px 以内、红色只在该改的地方算合格；不合格就删掉重出，同一张最多三次，再不行就改提示词。

`split` 输出 `layout.json`、`parts/` 和 `拆层总览.png`，并打印静止合成和原图的差。平均差应在 0.1 以下；脸上未归类的小块会列出来，它们留在脸皮上。

## See-through

[See-through](https://github.com/shitagaki-lab/see-through) 把一张立绘拆成脸、耳朵、脖子、前发、后发、帽子、衣服、眉毛、睫毛、眼白、眼珠、鼻子、嘴等二十来层，每层都是完整重画的，被挡住的部分也画出来了。它的图层边缘干净，每个像素只属于一层，模型动起来不会有碎点；自拆做不到这一点，所以最终图层必须走 See-through。

它给不了的，从自拆来：

- 表情：闭眼、笑眼、各种嘴型、眉形（它只拆立绘上画着的那一套）。闭嘴和鼻子也用自拆：它画得细、不对称。
- 前发分束：它的前发是一整块，按自拆的刘海、侧发分界切开。
- 被挡住、它没画的部分：帽子和刘海整个盖住头顶时的后发（V3、V8），挂件后面的衣服（V9）。
- 刘海下的额头（V5）：它在额头上画了刘海形状的影子，刘海一动就露出来。
- 它画了的被挡住的部分用它的原样：侧发下面、脸和脖子后面的后发，刘海和侧发互相盖住的地方。变体图和它深浅不同，补进去的范围正好是上面那层的形状，一摆就露出一块同形状的色块（[规则](规则.md)第 112 条）。
- 耳朵放在脸下面（它把耳朵叠在脸上，压住脸颊线）；领口按自拆的脖子挖开（它的衣服盖住了领口里的脖子）。
- 挂件单独一层（它把吊坠画在衣服上）。

反过来，眼镜和耳坠用它单独拆出的眼镜层、耳饰层：眼镜放在五官上面、头发下面，五官和脸皮上残留的镜框线去掉（各张变体里镜框画得略有偏差，会被当成五官抠进来）；垂下来的耳坠各成一个挂件，绕耳垂摆动。没有侧发和刘海时，它的前发并进后发。

```
python -m rigkit.seethrough fetch 素材/角色名/A0-base.png 素材/角色名/seethrough
python -m rigkit.seethrough split 素材/角色名 素材/角色名/layers 素材/角色名/layers-st --pad-top 90
```

旧版 `split` 拆好的文件夹，后发里被挡住的部分是从 V8 补的，侧发一摆会露出一块侧发形状的浅色。不用重拆，改回 See-through 原样后重新生成模型：

```
python -m rigkit.seethrough restore-back 素材/角色名 素材/角色名/layers-st
```

`fetch` 把立绘传到 See-through 的公开演示，取回 PSD（存为 `seethrough.psd`）并拆成每层一张整画布 PNG。传之前先问用户。

| 网站 | 速度 | 分辨率 | 额度 |
|---|---|---|---|
| Hugging Face（首选） | 几分钟一次 | 最高 1280 | 不登录时每天的免费显卡时间不一定够一次；免费账号的 Read token（`HF_TOKEN` 或 `~/.cache/huggingface/token`）约每天 1～2 次，额度从第一次用起 24 小时后恢复 |
| 魔搭 ModelScope（备用） | 要排队，一次可能半小时 | 最高 1536 | 免费，需要账号的访问令牌（`MODELSCOPE_API_TOKEN` 或 `~/.cache/modelscope/token`） |
| 本机（`--site local`，可选） | 整张约 21 分钟，只拆头部约 9 分钟（Apple M5 Pro，24 GB） | 1280 验证过 | 不传图，不限次数；装法见下面“本机跑 See-through” |

默认先试 Hugging Face，没跑成再换魔搭；`--site hf` 或 `--site modelscope` 只用一个。每个网站用它能给的最高分辨率，1536 的头发轮廓更深、眼睛更接近原画，补画也多一些（由 `split` 裁掉）。两个都没有额度时，等第二天，或在网页版、ComfyUI、自己的显卡上跑出 PSD，交给 `fetch 那个.psd 素材/角色名/seethrough`。

`split` 原样用 See-through 的图层，连颜色一起：静止时是 See-through 画的样子，比原画软一点。换来的是每个像素只属于一层，动起来没有碎点。它画错的地方由 `split` 按自拆修正，每一处都打印出来：

- 画到别的部件上的（帽子底下补出的帽檐盖到脸上）裁掉；
- 归错部件的配饰（发夹归进帽子）整块挪到原画上它所在的层；藏在别的部件下、和本部件不相连的（绒球放进上衣层）去掉；
- 整件漏画或成片画错的（没有裤子、裤子画成一块深色、脖子画短），以及侧发下面没画的后发，用自拆补；
- 睫毛整条放在头发下面，下睫毛只留原画有的笔画；
- 外套和袖子重叠的地方，每一块按哪种叠法更接近原画定上下（毛线帽外套的领尖、衣襟白边原来被袖子盖住）。

每条的来由见 [规则](规则.md) 的“See-through 合成”。

### 闭眼、笑眼交给 See-through

闭眼、笑眼默认是自拆的。图像模型改图时会把眼睛旁边的线条重画、偏一两个像素，贴着眼尾的线（脸颊和耳朵之间的轮廓线）就会被当成闭眼抠进来，边缘也毛躁。同一处改两次还在时，把这两张变体整张交给 See-through 拆：

```
python -m rigkit.seethrough fetch 素材/角色名/D5-eyes-closed.png 素材/角色名/seethrough-D5-eyes-closed
python -m rigkit.seethrough fetch 素材/角色名/D6-eyes-smile.png 素材/角色名/seethrough-D6-eyes-smile
python -m rigkit.seethrough split 素材/角色名 素材/角色名/layers 素材/角色名/layers-st --pad-top 90
```

`split` 看到 `seethrough-D5-eyes-closed`、`seethrough-D6-eyes-smile` 时，闭眼、笑眼改用它们的睫毛层，先按自拆的做法对位、校色差，打印 `Eye_Closed_L/R：See-through 拆 D5-eyes-closed 的睫毛层`。得到的层没有带进来的线，边缘平滑，保留双眼皮；和睁眼的睫毛一样比原画软一点。眉毛、嘴还没这样试过。

传到网站前同样先问用户，每张占一次额度。本机跑时加 `--site local --head-from 素材/角色名/seethrough`：用立绘那次的结果定头部范围，只拆头部，一张约 9 分钟。

### 本机跑 See-through

不传图，不限次数。在 Apple M5 Pro、24 GB 内存上验证过；Windows 和 NVIDIA 显卡没试过（那里可以直接用 See-through 自己的脚本跑出 PSD，再交给 `fetch 那个.psd`）。

装一次（要 git 和 [uv](https://docs.astral.sh/uv/)）：

```
git clone https://github.com/shitagaki-lab/see-through.git
cd see-through
git checkout df019de
git apply <skill 目录>/rigkit/vendor/see-through-mac.patch
uv venv --python 3.12 .venv
grep -v -E "^(PyQt6|qtpy|ipykernel|pytest|Cython|wheel|lpips|convnext_perceptual_loss)" requirements.txt > requirements-mac.txt
VIRTUAL_ENV=$PWD/.venv uv pip install torch==2.8.0 torchvision==0.23.0 -r requirements-mac.txt
```

然后把环境变量 `SEETHROUGH_DIR` 指向这个 `see-through` 目录（Python 默认用其中的 `.venv`，别处的用 `SEETHROUGH_PYTHON` 指定）。第一次运行从 Hugging Face 下载两个模型，共约 13 GB，不用账号；走 SOCKS 代理时先 `uv pip install socksio`。

```
python -m rigkit.seethrough fetch 素材/角色名/A0-base.png 素材/角色名/seethrough --site local
```

`--res` 默认 1280；1536 在 24 GB 上没试过。跑的时候显卡占满，VTube Studio 等程序会变卡；反过来 VTube Studio 开着时，See-through 慢一倍左右（只拆头部约 19 分钟）。`see-through-mac.patch` 和 `rigkit/seethrough_local.py` 改了什么、为什么改，见 [规则](规则.md) 第 104 条。

## 手势和脸红

See-through 合成完之后做。底图不是立绘，是最终图层的静止合成 `R0-rest.png`：手势和脸红照图层本身的画法画，打开手势时身体的画风不会跳。

```
python -m rigkit.extras 素材/角色名 素材/角色名/layers-st      # 第一次：写出 R0-rest.png
python -m rigkit.variants 素材/角色名 F1-blush P1-wave P2-explain P3-point
python -m rigkit.extras 素材/角色名 素材/角色名/layers-st      # 第二次：加进图层
```

- `Pose_*` 是这个姿势下脖子以下的整个身体，打开手势时替换身体组。只有变体改过的地方（抬起的手臂、袖子、原来手臂垂着的地方）取变体，其余仍是原来的身体层，所以只有手臂是新画的。
- `Cheek_Flush_L/R` 是一层纯色腮红，透明度是贴合变体的柔和椭圆，延伸到头发和下睫毛下面，摆头发时不露边。
- 结果在图层文件夹的 `手势和脸红.png`：每行是静止、变体、模型里打开后的样子。
- 手势提示词要求手离开头发、留一道白缝：手压在头发上时，那一块会被头发盖住。
- 图层改过（重跑了 `seethrough split` 或 `split`）以后，不用重出变体，再跑一次 `extras`：图层改过的地方，变体改了什么按 `R0-rest.png` 算，画面用改过的图层（[规则](规则.md)第 106 条）。改动落在手势要重画的地方（比如衣服换了颜色）时，还是删掉 `R0-rest.png` 和这四张变体，从第一次重来。

## 拆层怎么算（自拆）

- 看得见的范围来自 S1 和 V4 的色块，被挡住的部分来自逐张拿掉前层的变体。同色的前后头发靠差值分不开，色块图可以。
- 每张变体先整体对位，再按没变的像素校正颜色：图像模型每改一次，全图颜色都会漂一点。
- 静止时看得见的像素一律取自立绘，变体只用在被挡住的地方。半透明的边按下面一层反算颜色，所以图层叠回去和立绘逐像素一致。
- 五官用“有它”减“没有它”的差来抠（V3 − V5，D* − 对应的空白脸）。立绘上改的表情要和“立绘的空白脸”比：前面的头发取立绘，其余取 V5。直接和 V5 比，刘海和侧发的边都会混进表情层。
- 闭眼、笑眼抠图时离开脸的轮廓几个像素：D5、D6 会重画旁边的脸边线，连着睫毛被抠进来，闭眼时成了一条长斜线。
- 张嘴、O 型嘴补成实心：舌头和皮肤颜色接近，会被抠出缺口，嘴半张时成了往下垂的白条。
- 吊坠（V9）：立绘和 V9 的差就是吊坠，单独一层挂在身体上，底下的衣服取 V9。
- 长发：身体后面被挡住的长发，用两侧露出的发丝往里镜像补，头发甩离手臂时露出的是发丝，不是一片糊色。
- 脸皮层不允许吸收五官的像素。眼白漏抠一块时，它会显成空白，静止合成的差里能看到；否则会作为白色月牙画在脸皮上，只在闭眼时露出来。
- 人物和白底的分界：发丝之间、手臂和身体之间的细缝，按“发色和白色的混合”反算透明度；色块图里属于人物的白色部分（绒球、衬衫领）保持不透明。
- 被挡住、又没有变体补画的地方由代码补：脖子往上延伸到下巴后面、往下延伸到领口后面；后发沿发丝方向往下延伸到脸、耳朵、脖子后面。

## 自测

改了拆层代码后，用一个已经分好层的角色合成一套带偏移和噪点的变体，拆完和原图层比，再走完整个建模流程：


## 规则

- 只派“编辑”：整张图改一处，其余不动。不派“抽取”：只留一部分、其余涂白、排成部件图集——图像模型会把留下的部分重画一遍，放大、走样。
- 每次只给一张底图。整画布、原尺寸、原位置，白底。
- 幅度写成量：“眉头下移约眉长三分之一”有效，“更生气”无效。
- 要拆成前后两层的部位，按表里的链条一层层拿掉：每张只比上一张少一层，差就是那一层。
- 推理档位用 medium。出图质量由图像工具决定，调高推理档位不会让对位更准。

`提示词/角色一/` 是第一个角色用过的另一套变体（梳到脑后、换吊带、手臂平举、拿掉发髻），角色有发髻或需要完整肩颈时参考。
